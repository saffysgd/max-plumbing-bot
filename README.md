# Сантехнический бот MAX

Исходный код API-бота для заявок на сантехнические и отопительные работы. Бот подключается к MAX через Bot API и принимает события по HTTPS webhook.

## Что умеет бот

- Показывает услуги, цены, описание работ и FAQ.
- Собирает заявки по шагам, включая срочность, услугу, материал труб, тип соединения, опрессовку, описание, телефон и вложения.
- Сохраняет заявки в PostgreSQL.
- Ставит статус `аварийная`, если выбран выезд сегодня и в описании упомянуты прорыв или течь.

## Требования

- Node.js 24 или совместимая версия.
- pnpm.
- PostgreSQL, доступный с хостинга.
- Созданный бот MAX и его Bot API token.
- Публичный HTTPS-адрес на порту 443 для webhook.

## Настройка переменных

Добавьте переменные в защищённые настройки хостинга:

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `MAX_BOT_TOKEN` | Токен MAX Bot API |
| `NODE_ENV` | Установить в `production` |
| `MAX_WEBHOOK_URL` | Публичный адрес вида `https://your-domain.example/api/max/webhook` |
| `PORT` | Порт приложения; обычно его задаёт хостинг |

Не добавляйте реальные значения в GitHub. Файл `.env.example` содержит только пример. Отдельный webhook-секрет задавать не нужно: приложение вычисляет его из токена MAX и использует для регистрации и проверки запросов.

## Сборка и запуск

Подключите репозиторий к выбранному хостингу. Для сборки задайте:

```bash
pnpm install --frozen-lockfile
pnpm --filter @workspace/api-server run build
```

Команда запуска:

```bash
pnpm --filter @workspace/api-server run start
```

Команда запуска слушает `PORT`, заданный хостингом. Для локального запуска можно указать `PORT=8080`.

### Подготовка базы данных

Создайте PostgreSQL-базу на хостинге и задайте её строку подключения в `DATABASE_URL`. При первом запуске бот автоматически создаст таблицы `bot_sessions` и `plumber_applications`; вручную запускать команду миграции не нужно. Пользователю базы нужны права на создание таблиц. Если таблицы уже существуют, запуск их не изменяет.

## MAX webhook

1. Настройте домен и TLS на хостинге так, чтобы внешний адрес использовал HTTPS на стандартном порту 443.
2. Установите `MAX_WEBHOOK_URL`, например `https://your-domain.example/api/max/webhook`.
3. Запустите приложение с `NODE_ENV=production` и `MAX_BOT_TOKEN`.

При старте production-сервис зарегистрирует webhook в MAX автоматически. Не запускайте эту регистрацию из development-окружения.

Проверить состояние можно по адресам:

- `GET /api/healthz` — доступность API.
- `GET /api/max/status` — наличие токена, базы и production webhook-настроек.

## Код бота

- `artifacts/api-server/src/lib/plumber-bot.ts` — меню и сценарий заявок.
- `artifacts/api-server/src/lib/max-api.ts` — запросы к MAX Bot API.
- `artifacts/api-server/src/routes/max-bot.ts` — webhook и проверка секрета.
- `lib/db/src/schema/bot.ts` — схема диалогов и заявок.

В репозитории также сохранены общие пакеты рабочего пространства и компонентный mockup sandbox; для запуска бота используйте только команды API-сервера выше.
